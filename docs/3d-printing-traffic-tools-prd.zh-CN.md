# zaps.work 3D 打印流量工具需求文档

> 版本：v1.0  
> 更新时间：2026-07-16  
> 状态：待评审  
> 负责人：产品 / 设计 / 开发  
> 第一阶段范围：耗材成本计算器、打印机每小时运行成本计算器

## 1. 背景

zaps.work 已上线完整的 3D 打印成本与报价计算器，支持耗材、机器时间、电力、人工、失败风险、包装、利润率、税费以及 PDF/CSV 导出。

Google Search Console 最近 7 天已经出现以下相关查询：

- `druckkostenrechner`
- `druckkosten berechnen`
- `3d druck kosten berechnen`
- `3d druck kosten pro stunde`
- `3d drucker kosten pro stunde`
- `3d printing price calculator`
- `3d printing quote calculator`

目前样本量较小，只能证明 Google 已开始将网站与“3D 打印成本、每小时成本和报价”关联，不能据此断言关键词的长期搜索量。第一阶段需要用两个意图清楚、开发成本较低的单用途工具验证流量机会，再根据 28 天数据决定是否继续扩展。

## 2. 产品目标

### 2.1 核心目标

1. 用低门槛的单用途工具承接 3D 打印长尾搜索流量。
2. 让用户在 30 秒内得到一个可信、可解释的核心结果。
3. 将需要完整核算的用户导向现有 3D 打印成本与报价计算器。
4. 加深网站在“3D 打印成本核算”主题上的内容和内部链接结构。

### 2.2 优先级原则

本阶段按以下顺序做决策：

1. 搜索流量机会。
2. 工具可用性与结果可信度。
3. 与现有产品的复用程度。
4. 功能完整度与高级工作流。

### 2.3 非目标

第一阶段不建设：

- 独立的 3D 打印售价计算器。
- G-code、STL、3MF 文件解析。
- 打印机型号和实时功耗数据库。
- 耗材库存与打印农场管理。
- 用户账户、云端保存和订单管理。
- 自动提供行业平均报价或承诺最终成交价。

## 3. 产品结构与工具边界

### 3.1 工具关系

```text
耗材成本计算器 ───────┐
                      ├─→ 完整 3D 打印成本与报价计算器 ─→ PDF / CSV / 客户报价
打印机每小时成本计算器 ┘
```

两个新工具负责回答单一问题，现有完整工具负责组合材料、机器、人工、风险和利润。

### 3.2 职责边界

| 工具 | 用户问题 | 默认包含 | 默认不包含 |
| --- | --- | --- | --- |
| 耗材成本计算器 | 这个模型或批次消耗的耗材值多少钱？ | 线盘价格、净重、模型用量、数量、损耗 | 机器、电力、人工、利润 |
| 打印机每小时运行成本计算器 | 打印机自身每运行一小时花多少钱？ | 折旧、电费、维护 | 耗材、人工、利润 |
| 完整成本与报价计算器 | 完成这个订单一共花多少钱，应该报多少？ | 耗材、机器、电力、人工、失败风险、包装、利润和税 | 文件自动解析、行业均价 |

### 3.3 命名要求

“每小时成本”页面必须明确使用“打印机每小时运行成本”，不能暗示其默认包含耗材、人工或客户报价。

建议页面名称：

- 英文：`3D Printer Cost per Hour Calculator`
- 德文：`3D-Drucker-Kosten pro Stunde Rechner`
- 简体中文：`3D 打印机每小时运行成本计算器`

## 4. 目标用户与使用场景

### 4.1 场景 A：个人玩家计算模型耗材成本

用户已经从切片软件获得模型用量，希望知道本次打印消耗了多少钱的材料。

已知数据：

- 线盘购买价格与净重。
- 模型使用克数或耗材长度。
- 计划打印数量。

成功标准：

- 用户在 30 秒内得到单件成本。
- 用户能看懂损耗如何影响成本。
- 用户需要完整成本时，可以带着结果进入主工具。

### 4.2 场景 B：准备购买打印机的人评估运行成本

用户希望比较设备价格、电费和使用强度带来的长期成本。

已知数据：

- 打印机价格。
- 预计使用年数和每周运行小时。
- 设备功率与当地电价。

成功标准：

- 用户得到每小时设备成本及其构成。
- 页面明确提示结果不包含耗材和人工。
- 用户不需要猜测抽象的“设备寿命小时数”。

### 4.3 场景 C：接单打印者核算具体订单

用户先使用一个轻量工具得到耗材成本或机器费率，然后进入完整工具加入打印时间、人工、失败率和目标利润。

成功标准：

- 新工具的结果可以无歧义地用于完整工具。
- 用户不需要重复输入已经计算过的关键数据。
- 完整工具仍是成本、售价与正式报价的唯一主入口。

## 5. P0：耗材成本计算器

### 5.1 页面定位

回答：

> 已知线盘价格和模型耗材用量，这个模型或批次的材料成本是多少？

建议稳定 URL：

- 英文：`/calculators/filament-cost-calculator`
- 德文：`/de/calculators/filament-cost-calculator`

URL 沿用网站现有的“语言前缀 + 稳定英文 slug”约定，德语页面通过标题、H1、正文和元数据匹配德语查询，不另建重复的本地化 slug。

### 5.2 输入字段

#### 基础输入

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 线盘价格 | 是 | 按当前货币提供合理示例值 | 用户实际购买价 |
| 线盘净重 | 是 | 1000 g | 不包含空线盘重量 |
| 单件模型耗材用量 | 是 | 100 g | 默认使用切片软件的完整用量 |
| 打印数量 | 是 | 1 | 1–100,000 |
| 额外损耗率 | 否 | 5% | 支撑、裙边、换料和一般损耗的合并预留 |

#### 高级输入

- 输入方式：重量 / 长度。
- 材料：PLA、PETG、ABS、TPU、其他。
- 耗材直径：1.75 mm、2.85 mm、自定义。
- 自定义材料密度。

第一版默认展示重量模式；长度与密度换算放在可展开的高级区域，不阻碍首次计算。

### 5.3 计算规则

#### 重量模式

```text
每克价格 = 线盘价格 ÷ 线盘净重
单件计费耗材 = 单件模型用量 × (1 + 损耗率)
单件耗材成本 = 单件计费耗材 × 每克价格
批次耗材成本 = 单件耗材成本 × 数量
一卷可打印件数 = floor(线盘净重 ÷ 单件计费耗材)
批次后理论余量 = max(0, 线盘净重 - 单件计费耗材 × 数量)
```

#### 长度模式

```text
截面积 = π × (耗材直径 ÷ 2)²
耗材体积 = 截面积 × 耗材长度
耗材重量 = 耗材体积 × 材料密度
```

长度、体积与密度必须先换算到一致单位，再进入重量模式的成本公式。

### 5.4 结果展示

主结果：

- 单件耗材成本。

辅助结果：

- 每克耗材价格。
- 单件计费耗材重量。
- 损耗成本。
- 批次耗材总量与总成本。
- 一卷理论可打印件数。
- 当前批次完成后的理论余量；若超过一卷，显示所需完整线盘数和不足量。

### 5.5 交互要求

- 修改输入后即时更新结果。
- 首屏保持输入简短，不要求注册。
- 每个输入字段说明数据从哪里获取。
- “复制结果”只复制成本摘要，不包含任何用户自由文本。
- 主要 CTA：`计算完整打印成本`。
- CTA 将线盘价格、净重、模型用量、数量和损耗率带入现有完整工具；不得覆盖用户已有的浏览器偏好。

### 5.6 边界情况

- 线盘净重、模型用量为 0 时不得执行除法，给出字段级提示。
- 当单件计费耗材大于一卷净重时，显示“单件需要多于一卷”，不能显示 0 件后停止解释。
- 当批次需要多卷时，正确向上取整所需线盘数。
- 自定义密度必须大于 0。
- 极大、负数、空白、非数字输入不得产生 `NaN`、`Infinity` 或页面崩溃。
- 货币切换必须转换金额值，而不只是更换货币符号。

## 6. P0：打印机每小时运行成本计算器

### 6.1 页面定位

回答：

> 不含耗材和人工时，这台打印机每运行一小时的设备成本是多少？

建议稳定 URL：

- 英文：`/calculators/3d-printer-cost-per-hour`
- 德文：`/de/calculators/3d-printer-cost-per-hour`

### 6.2 输入模式

#### 简单模式（默认）

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 打印机购买价格 | 是 | 按当前货币提供合理示例值 | 包含用户希望摊销的基础设备成本 |
| 预计使用年数 | 是 | 3 年 | 1–20 年 |
| 每周运行小时 | 是 | 30 小时 | 用于估算总运行小时 |
| 平均打印功率 | 是 | 120 W | 推荐使用实测平均功率；没有时可用合理估计 |
| 当地电价 | 是 | 按当前货币提供示例值 / kWh | 用户电费账单中的单位电价 |
| 年度维护成本 | 否 | 0 | 喷嘴、热床、润滑和常规维修等 |
| 预计残值 | 否 | 0 | 设备使用期结束后的预计价值 |

#### 高级模式

用户可直接输入：

- 预计总运行寿命小时。
- 升级配件成本。
- 每小时维护成本，替代年度维护成本。

高级模式改变摊销假设，但结果结构保持一致。

### 6.3 计算规则

#### 简单模式

```text
预计总运行小时 = 使用年数 × 52 × 每周运行小时
可折旧金额 = max(0, 购买价格 + 升级配件成本 - 预计残值)
每小时折旧 = 可折旧金额 ÷ 预计总运行小时
每小时电费 = 平均功率 ÷ 1000 × 每 kWh 电价
每小时维护成本 = 年度维护成本 ÷ (52 × 每周运行小时)
每小时机器运行成本 = 每小时折旧 + 每小时电费 + 每小时维护成本
```

#### 高级模式

```text
每小时折旧 = 可折旧金额 ÷ 预计总运行寿命小时
每小时机器运行成本 = 每小时折旧 + 每小时电费 + 用户输入的每小时维护成本
```

### 6.4 结果展示

主结果：

- 每小时机器运行成本。

成本拆解：

- 每小时折旧。
- 每小时电费。
- 每小时维护成本。
- 三项占比。

按用户使用强度提供：

- 每周预计机器运行成本。
- 每月预计机器运行成本，按 `每周成本 × 52 ÷ 12` 计算。
- 每年预计机器运行成本。

可选的“估算一次任务”区域：

- 用户输入打印小时和分钟。
- 输出本次任务的机器运行成本。
- 该区域仍不包含耗材、人工和利润。

### 6.5 交互和解释要求

- 结果卡必须持续显示：`不包含耗材、人工、失败风险和利润`。
- 平均功率字段解释“额定最大功率”和“打印平均功率”的区别。
- 预计使用年数与每周小时改变时，折旧结果即时更新。
- 不自动猜测每小时耗材克数。
- 主要 CTA：`加入耗材和人工，计算完整项目成本`。
- CTA 将计算得到的每小时机器费率带入现有完整工具的 `machineRate`。

### 6.6 边界情况

- 每周运行小时为 0 时不计算折旧，提示用户输入有效使用强度。
- 残值高于设备与升级总价时，可折旧金额按 0 处理并展示说明。
- 年度维护成本与每小时维护成本不能同时重复计入。
- 简单模式与高级模式切换后不能静默混用两套寿命数据。
- 极端、负数、空白、非数字输入不得产生错误结果或页面崩溃。
- 货币切换必须转换购买价、残值、维护费和电价。

## 7. 与现有完整工具的衔接

### 7.1 复用要求

- 耗材每克成本、损耗和货币换算应复用共享的纯计算函数。
- 每小时机器成本作为现有完整工具 `machineRate` 的来源之一。
- 新页面与现有工具显示同一输入时，结果必须一致。
- 不复制一套独立且可能漂移的公式实现。

### 7.2 数据带入

允许使用 URL 参数或浏览器会话状态带入非敏感计算参数。具体实现由开发阶段决定，但必须满足：

- 用户点击 CTA 后无需重新输入关键数字。
- 参数不包含姓名、邮箱、电话、公司、客户或项目自由文本。
- 用户可以在完整工具内修改所有带入值。
- 带入值不应永久覆盖用户原有偏好，除非用户主动保存。

## 8. SEO 与内容要求

### 8.1 搜索意图隔离

| 页面 | 主意图 | 不争夺的意图 |
| --- | --- | --- |
| 耗材成本 | 每克、每件、一卷耗材成本 | 完整报价、机器折旧 |
| 每小时机器成本 | 设备每小时折旧、电费与维护 | 耗材成本、客户收费 |
| 完整成本工具 | 项目总成本与客户报价 | 单一材料换算 |

### 8.2 页面最低内容

每个新页面必须包含：

- 首屏可直接使用的计算器。
- 明确说明结果包含和不包含什么。
- 可复核的计算公式。
- 至少一个完整示例。
- 每个关键字段的数据获取说明。
- 与现有完整工具和另一个流量工具的内部链接。
- 4–6 个与本页面意图直接相关的 FAQ。
- 独立的 title、description、H1、canonical、hreflang 和结构化数据。

### 8.3 首发语言

第一阶段内容优先级：

1. 德语：承接已经出现的 `3d druck ... pro stunde` 等查询。
2. 英语：覆盖更广泛的国际搜索并作为默认语言。

其他语言只有在完整翻译、元数据、公式说明和 FAQ 全部就绪后才进入索引与 hreflang，不发布只有表单标签的薄页面。

### 8.4 避免关键词互相竞争

- 新页面 title 不使用与现有 `3D Print Cost Calculator` 完全相同的主标题。
- “每小时机器成本”正文不得宣称自己是完整报价计算器。
- “耗材成本”正文不得用大量篇幅覆盖折旧、人工和利润计算。
- 现有完整工具增加两个新工具的说明链接，但保持其主关键词和 canonical 不变。

## 9. 数据与隐私

### 9.1 推荐事件

- `calculator_used`：用户产生有效结果。
- `summary_copied`：用户复制计算摘要。
- `full_calculator_clicked`：用户从轻量工具进入完整工具。
- 页面访问继续由现有网站分析记录。

### 9.2 允许记录

- 工具 slug。
- 语言、货币和单位模式。
- 是否使用高级模式。
- 是否使用损耗、长度输入或维护成本等功能开关。
- 不可逆的范围型结果，例如耗材用量区间或每小时成本区间；只有确实用于产品决策时才记录。

### 9.3 禁止记录

- 任何客户、公司或项目自由文本。
- 用户上传文件；第一阶段本身不支持文件上传。
- 能够识别个人或具体订单的信息。

分析接口必须继续使用严格白名单校验，未知字段直接拒绝。

## 10. 可用性要求

- 无需登录即可完成计算。
- 移动端首屏可以开始输入，不先展示长篇 SEO 内容。
- 基础模式字段不超过首次任务所需的最小集合。
- 高级字段默认折叠，但可以被搜索、键盘和辅助技术访问。
- 输入标签必须包含单位，不能只依赖占位文本。
- 结果变化不能造成页面大幅跳动。
- 默认值必须明确标注为示例或假设，不伪装成行业标准。
- 公式、字段提示和错误信息全部随语言切换。

### 11.2 产品与交互

- [ ] 每小时成本页面明确提示不包含耗材和人工。
- [ ] 耗材页面能够解释损耗前后的差额。

- [ ] 发布后第 7 天和第 28 天完成数据复盘。

## 12. 发布与决策门槛

### 12.1 发布顺序

1. 耗材成本计算器，英语与德语。
2. 打印机每小时运行成本计算器，英语与德语。
3. 补充完整工具与新页面之间的内部链接和结果带入。
4. 观察 28 天后再决定下一个工具。

### 12.2 核心指标

| 阶段 | 指标 |
| --- | --- |
| 搜索获取 | 展示量、非品牌查询数、平均排名、自然点击率 |
| 工具使用 | 有效计算次数、有效计算率、复制结果率 |
| 产品导流 | 进入完整成本工具的点击率、带参到达成功率 |
| 价值结果 | 完整工具使用率、PDF/CSV 导出率 |

### 12.3 28 天决策规则

| 信号 | 下一步 |
| --- | --- |
| 有展示且排名 11–30 | 优化对应页面标题、首屏说明、示例、FAQ 和内部链接 |
| 展示增长但点击率低 | 检查搜索意图与标题描述是否匹配，而不是立即新增工具 |
| 使用率高且导流率高 | 扩展相邻的单用途工具或其他语言 |
| 访问高但有效计算率低 | 优先修复默认值、字段解释和移动端交互 |
| 导流高但完整工具完成率低 | 审计参数带入、字段重复和完整工具复杂度 |
| 28 天仍无有效展示 | 暂停扩展同类页面，重新验证关键词和收录状态 |

### 12.4 后续候选项

只有数据支持时，按以下顺序评估：

1. 树脂 3D 打印成本计算器。
2. 3D 打印电费计算器。
3. 耗材长度/重量换算器独立入口。
4. 一卷耗材可打印件数工具。
5. 独立售价与利润率计算器。

## 13. 待评审问题

以下问题在进入开发前确认，但不影响当前需求边界：

1. 长度模式是随耗材成本计算器首发，还是作为第二阶段独立流量页上线。
2. 德语内容由谁完成自然语言校对。
3. 计算结果带入主工具使用 URL 参数还是会话状态。
4. 新工具是否首发支持结果复制，还是与分析事件补齐一起上线。
5. 其他七种语言是首发完整交付，还是在德语、英语验证后逐步开放索引。

## 14. 最终产品判断

第一阶段不以“更多页面”为成功标准，而以两个页面能否分别解决独立问题并把高意向用户送入完整报价工具为准。

最终结构应保持清楚：

- 耗材成本计算器只解决材料成本。
- 打印机每小时运行成本计算器只解决设备运行成本。
- 现有完整计算器统一解决项目总成本、利润与正式报价。

任何新增字段或页面，如果不能强化这三个边界之一，应推迟到数据验证之后。
